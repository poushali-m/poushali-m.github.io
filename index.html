Troubleshooting Case Studies

Worked scenarios showing how I diagnose, fix and verify common helpdesk problems, from the first question to the ticket notes.

Case Study 01
Windows Service Failure: Print Spooler
User reports: printer not found after Windows Update. No queue visible, other users on the same network unaffected.
Diagnosis
Opened Event Viewer (System log) and found Event ID 7034: Print Spooler service terminated unexpectedly. Checked services.msc and confirmed Spooler was stopped and set to Manual instead of Automatic.
Resolution
Cleared corrupted driver files from C:\Windows\System32\spool\drivers via PowerShell, set Spooler back to Automatic, restarted service.
Verification
Confirmed printer reappeared in Devices and Printers, test page printed successfully. Logged resolution in ticket with steps for recurrence.
Windows 11 Event Viewer PowerShell Services
Case Study 02
DNS Resolution Failure: Site Unreachable
User reports: internal intranet site timing out. External sites work fine. Issue is isolated to this workstation.
Diagnosis
Ran ping intranet.corp: request timed out. Ran nslookup intranet.corp: returned wrong IP (stale cache). Ran ipconfig /all: DNS server pointed to 8.8.8.8 (Google) instead of the internal DNS server, likely changed during VPN install.
Resolution
Updated DNS server address in network adapter settings to the correct internal DNS IP. Flushed DNS cache with ipconfig /flushdns and registered with ipconfig /registerdns.
Verification
nslookup now returned correct internal IP. Site loaded. Escalated root cause (VPN installer overwriting DNS) to network team to prevent recurrence.
DNS nslookup ipconfig Networking
Case Study 03
MFA Enforcement Review: Microsoft Entra ID
During my internship at CyPro, I managed approximately 30 user identities in Microsoft Entra ID and identified that MFA was not consistently enforced, leaving accounts exposed to unauthorised access.
Diagnosis
Reviewed sign-in logs to identify accounts without MFA registered. Assessed available authentication methods (Microsoft Authenticator, SMS, hardware token) to determine the most practical option for the team and the impact on day-to-day users.
Proposal
Proposed an MFA enforcement policy, outlining the security benefit and user impact. Recommended a phased rollout starting with a pilot group to avoid locking users out. Flagged the need for administrator approval before configuring the Conditional Access policy.
Outcome
Proposal was approved and taken forward. Supported users in registering their authentication methods and verified enforcement through sign-in logs. All 30 identities brought into MFA compliance, significantly reducing the risk of credential-based attacks.
Microsoft Entra ID MFA Conditional Access Identity & Access Azure AD
Case Study 04
Account Lockout: User Cannot Sign In
User reports: “account locked” message when signing in on Monday morning after changing their password last week. Phone and laptop both affected.
Diagnosis
Confirm the user’s identity first, following the verification policy. Check the account status in Active Directory Users and Computers, or the failure reason in the Entra ID sign-in logs (error 50053 means locked by Smart Lockout). On a domain controller, Event ID 4740 shows which device is causing the lockouts. Most often it is an old password saved on a phone mail app, mapped drive or Credential Manager.
Resolution
Unlock the account, then have the user update the saved password on every device that still uses the old one. If needed, reset the password with “must change at next sign-in” and share the temporary password through an approved secure channel, never by email or chat.
Verification
User signs in successfully on laptop and phone. Watch for a repeat lockout over the next 30 minutes. Record the root cause (stale saved credentials) and advice given in the ticket. If lockouts continue or come from unknown locations, escalate to the security team as possible password guessing.
Active Directory Microsoft Entra ID Event ID 4740 Password Reset
Case Study 05
VPN Failure: Remote User Cannot Connect
User reports: working from home, VPN client shows “connection timed out”. Home internet and Teams work normally.
Diagnosis
Confirm the internet works (ping 8.8.8.8), then check whether other remote users are affected to separate a single-user fault from a gateway outage. Check the client version, the saved credentials and MFA prompt, the account status, and the system clock (a wrong clock breaks certificate checks). Test on a mobile hotspot: if it connects there, the home router or ISP is blocking VPN traffic.
Resolution
Fix the cause found: update or reinstall the client, correct the clock, re-register MFA, unlock or reset the account, or advise the user to switch networks. If several users are affected or the gateway is not responding, escalate to the network team with the error message, time, affected users and the checks already done.
Verification
User connects and opens an internal resource by name, such as the intranet or a file share, which also confirms DNS works over the tunnel. Record the cause and fix in the ticket. If it was an escalation, keep the user updated until it is closed.
VPN Troubleshooting Windows 11 Escalation
Case Study 06
Wi-Fi Connected but No Internet
User reports: laptop shows “connected” to the office Wi-Fi but no website loads. Colleagues nearby are fine.
Diagnosis
Run ipconfig /all. An address starting 169.254 means the laptop failed to get an IP from DHCP. If it has a valid address, test the gateway (ping the default gateway), then an external IP, then a website name to separate a network fault from a DNS fault. Check whether the problem follows the device or the location.
Resolution
Run ipconfig /release then ipconfig /renew. If that fails, toggle the adapter, forget and rejoin the network, and update the Wi-Fi driver. If several devices cannot get an address, the DHCP scope may be exhausted or the server down, so escalate to the network team.
Verification
The laptop has a valid IP, gateway and DNS server. ping an external address and nslookup a website both succeed, and a page loads. Log the cause and fix in the ticket.
DHCP ipconfig Wi-Fi Networking
